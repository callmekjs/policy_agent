## 1. 다섯 줄 요약

1. **`HS-` 로 시작하는 이름표를 붙이면 그 문단은 검사를 통째로 건너뛴다.**
   똑같은 거짓 문장이 이름표 `P-99`면 **7개 규칙**에 막히고 `HS-99`면 **0개**다.
2. 그 길로 넣은 `재석 250인`·`2026년 1월 1일`·`홍길동`이 **내려받은 파일에
   그대로 들어간다.**
3. 모든 사실에 **"틀렸다"를 눌러도** 다운로드가 200으로 나가고, 틀렸다고 한
   값이 파일에 그대로 있다.
4. **부칙은 글만 지우면 통과한다.** `supplementary_rule_ids`만 남기면
   `시행일` 문구가 사라져도 `APPLIED`다.
5. **`K4`는 진짜로 지켜진다.** 11가지 방법으로 실패시켰는데 11번 다 이전
   초안이 그대로였다. 오늘 만든 시험 중 아무것도 안 지키는 것은 **0개**다.

## 2. 왜 뚫렸나 — 뿌리는 하나다

처음 초안을 만들 때 `_write_draft`는 AI가 쓴 `HS-` 문단을 **버리고 Harness가
다시 만든다.**

```python
# orchestrator.py _write_draft
if p.section_kind not in HARNESS_OWNED
and not p.paragraph_id.startswith(HARNESS_ID_PREFIX)
```

`revise()`에는 이 걷어내기가 **없다.** 그런데 `check_draft`는 `HS-` 문단을
"Harness가 만든 것"으로 보고 검사에서 뺀다(`agent_parts`). 그래서 처음
초안에서는 안전하던 규칙이, 수정본에서는 **AI가 마음대로 쓰는 자리**가 된다.

`_check_candidate`가 `fixed_labels`에 넣는 줄도 같은 자리를 가리킨다.

```python
*[p.text for p in candidate.paragraphs if p.paragraph_id.startswith("HS-")]
```

처음 초안 때 이 `candidate`는 **Harness가 방금 다시 만든 것**이고, 수정본 때
이 `candidate`는 **AI가 준 것**이다. 인자 이름은 같지만 **믿을 수 있는지가
다르다.**

이것은 13차 검토가 적어 둔 결론과 같은 이야기다 — *"값을 믿는 대신 자리를
믿는다."* 부칙 자리는 그렇게 고쳐서 13종을 막았다. 그런데 그 "자리"의
표시가 **`HS-` 라는 글자 세 자**이고, 수정본에서는 그 글자를 AI가 직접 쓴다.

## 3-1. `K1` 보호 사실 — 여섯 가지로 때렸고 여섯 다 막혔다

**확인 없이 보호가 붙는 길은 없다.**

```
=== K1-a  확인 없이 보호가 붙는 길이 있는가 ===
  확인 전 protected 개수: 0
  reviews=[] 로 apply -> protected: 0
  전부 WRONG -> protected: 0
  FactVerdict 값 전부: ['OK', 'WRONG']
```

판정은 `OK`·`WRONG` 둘뿐이라 "안 본 것"과 "틀렸다"가 섞일 자리가 없다.
`apply_reviews`는 **매번 새로 계산**해서 덮으므로, 예전에 붙은 보호가 남는
일도 없다.

**값을 건드리는 여섯 길이 다 막혔다.**

```
[막힘] K1-b 제목·리드·요약만 '원안가결'->'부결'  rules=['CLAIM_VALUE_NOT_ANCHORED','TOPIC_VALUE_MISMATCH','WORD_NOT_IN_LEDGER']
[막힘] K1-c 제목에서 값 뒤섞기                  rules=['CLAIM_VALUE_NOT_ANCHORED','TOPIC_VALUE_MISMATCH']
[막힘] K1-d 의안번호를 모든 글에서 제거(근거 유지) rules=['CLAIM_VALUE_NOT_ANCHORED','PROTECTED_FACT_CHANGED','TOPIC_VALUE_MISMATCH']
[막힘] K1-e '원안가결로 처리되지 않은'            rules=['LEDGER_VALUE_NEGATED','WORD_NOT_IN_LEDGER']
```

**질문받은 것 — `revision_gate`가 문단만 보는가?** 아니다. `_all_text`는
제목·리드·요약·문단을 **전부** 본다. 다만 **그 넓이를 지키는 시험이 없다**
(아래 11절 `T8`).

**`PROTECTED_CANDIDATE_KINDS`는 옳은가.** 원장에 실제로 나오는 종류는 5개이고
그중 `BILL_TITLE` 하나가 빠져 있다.

```
  원장에 실제로 나온 종류: ['BILL_IDENTITY','BILL_TITLE','PLENARY_DECIDED_ON','PLENARY_RESULT','PROVISION_CHANGE']
  보호 후보 목록:        ['BILL_IDENTITY','PLENARY_DECIDED_ON','PLENARY_RESULT','PROVISION_CHANGE']
  후보에서 빠진 종류:    ['BILL_TITLE']
```

빠뜨린 이유가 코드에 적혀 있다 — 가짜 추출기가 인용된 다른 법률까지
`BILL_TITLE`로 뽑는 문제가 4일차 `남은 일`이라, 확실하지 않은 것을 보호하지
않는다는 것이다. **판단이 근거를 갖고 있으므로 차단으로 올리지 않는다.**
다만 4일차 `H1`이 정확히 `BILL_TITLE` 값을 통로로 쓰므로, 6일차에 그 문제를
고칠 때 **함께 다시 봐야 한다** (`남은 일`).

## 3-2. `K2` 부칙 — **글만 지우면 통과한다 (BLOCKED)**

`REVISION_DROPPED_RULE`은 **`supplementary_rule_ids` 집합만 견준다.** 글은 안
본다. 그래서 번호만 남기고 문장을 지우면 검사가 아무것도 못 본다.

```
=== K2 끝까지 · 부칙 글만 지우고 rule_ids 는 남긴다 ===
  outcome=APPLIED blocking=[] dv=2
  고치기 전 파일에 '시행' 있음: True  / 고친 뒤: False
  고치기 전 부칙 줄: ['부칙(EFFECTIVE_DATE)은 "이 법은 공포한 날부터 시행한다."라고 제안하고 있습니다. 아직 확정 전입니다.']
  고친 뒤   부칙 줄: ['관련 내용은 추후 안내한다.']
  남아 있는 supplementary_rule_ids: ['SR-01']
```

읽는 사람은 **언제부터 적용되는지 알 수 없다.** `SR-01`은 그대로 붙어 있어
되짚어 보아도 "부칙이 있다"고 나온다.

문단을 통째로 지우는 쪽은 잘 막는다(대조군).

```
[막힘] K2-a 부칙 문단 삭제  rules=['REVISION_DROPPED_RULE','SUPPLEMENTARY_RULE_DROPPED']
[막힘] K2-c 부칙 문단 삭제 + rule_ids 를 본문에 붙임  rules=['RULE_VALUE_NOT_ANCHORED']
```

**뿌리가 둘이다.** 첫째, `REVISION_DROPPED_RULE`이 글을 안 본다. 둘째, 부칙
문단이 `HS-04`라서 4일차 검사도 건너뛴다. 이름표만 `PP-04`로 바꿔 같은 짓을
하면 4일차 검사가 잡는다.

```
[막힘] K2-b' 이름표를 PP-04 로 바꿔 같은 짓  rules=['HARNESS_OWNED_SECTION','RULE_VALUE_NOT_ANCHORED','WORD_NOT_IN_LEDGER']
  check_revision 단독 판정: []
```

## 5. `L1` — 수정본은 처음 초안과 **다른 검사를 받는다 (BLOCKED)**

### 5-1. `check_draft` 인자를 하나씩 맞대 봤다

| 인자 | 처음 초안 (`_write_draft`) | 수정본 (`_check_candidate`) | 같은가 |
|---|---|---|---|
| `candidate` | Harness가 `HS-`를 다시 만든 것 | **AI가 준 것 그대로** | **다르다** |
| `ledger` | `build_fact_ledger` 결과 | `run.fact_ledger` (같은 값 + `protected` 표시) | 같다 |
| `final_text` | `resolve_final_text` 결과 | `run.resolved_final_text` | 같다 |
| `article_set` | `parse_changed_articles` 결과 | `run.changed_article_set` | 같다 |
| `normalized` | `normalize_source(s.raw_text)` | 같은 식으로 다시 계산 | 같다 |
| `announcement_subject` | `run.announcement_subject_input or ""` | `run.announcement_subject_input or ""` | 같다 |
| `template` | `load_template(...)` | `load_template(...)` | 같다 |
| `has_statement_source` | `sources` | `run.sources` | 같다 |
| `fixed_labels` 앞 6개 | 상수 + `basis_date` | 상수 + `run.basis_date.isoformat()` | 같다 |
| **`fixed_labels` 마지막** | **Harness가 방금 만든 `HS-` 글** | **AI가 준 `HS-` 글** | **다르다** |

**함수 이름과 인자 이름은 같은데, 두 자리에서 값의 출처가 다르다.**

### 5-2. 숫자로 — 같은 거짓 문장, 이름표만 바꿨다

문장: `이번 개정으로 재석 250인 중 찬성 248인으로 가결되었으며 2026년 1월 1일부터 전면 시행된다.`

```
  이름표 P-99     -> 막은 규칙 7개 ['CLAIM_WITHOUT_FACT','COUNT_NOT_IN_LEDGER','DATE_NOT_IN_LEDGER','EFFECTIVE_DATE_NEEDS_RULE','NUMBER_NOT_IN_LEDGER','PREMATURE_EFFECT_CLAIM','WORD_NOT_IN_LEDGER']
  이름표 HS-99    -> 막은 규칙 0개 []
  이름표 HSX-99   -> 막은 규칙 7개 [...위와 같음...]
  이름표 HS       -> 막은 규칙 8개 [...]
  이름표 HS-01x   -> 막은 규칙 1개 ['IDENTIFIER_SHAPE_INVALID']
```

**`HS-` 두 글자와 뒤의 숫자 두 자리, 그것뿐이다.**

이 문장 하나가 4일차 합격선 **넷을 동시에 어긴다.**

- `F1` 자료에 없는 수 `250`·`248`, 없는 날짜 `2026년 1월 1일`
- `F4` 근거로 달린 `fact_id`가 하나도 없다
- `H1` 본회의 의결을 `전면 시행`으로 말한다
- `H2` 부칙 근거 없이 시행일을 쓴다

### 5-3. 진짜 `revise()`로 끝까지 밀었다

```
=== 진짜 revise() 로 HS- 주입을 끝까지 밀어 본다 ===
  outcome=APPLIED  blocking=[]
  draft_version 1 -> 2   state=REVIEW_READY
  초안에 실렸는가: True  ['이번 개정으로 재석 250인 중 찬성 248인으로 가결되었으며 2026년 1월 1일부터 전면 시행된다.']
```

**막지 않았고, 새 판이 되었고, 초안에 실렸다.**

### 5-4. 발표 주체도 같은 길로 위조된다

```
=== 발표 주체 위조도 끝까지 미는가 ===
  outcome=APPLIED blocking=[] dv=2
  HS-03: ['발표 주체: 대한민국 국회 사무총장 홍길동 · 배포 예정일: 2025-11-01']
  '홍길동' in markdown -> True
```

`announcement_subject_fact_id`는 그대로라 `ANNOUNCER_CHANGED`가 안 뜬다.
그래서 **`K3` 번호로는 안 걸리고 `L1`(`F1` 인명)으로 걸린다.**

### 5-5. 뿌리를 갈라서 확인했다

`fixed_labels`가 **본문까지 세탁해 주지는 않는다.** 아래 (2)·(4)가 그 증거다.
문제는 **`HS-` 문단 자체가 검사 밖**이라는 것이다.

```
(1) 본문에만 지어낸 기관명 (HS-03 은 그대로)  -> [막힘]   ['WORD_NOT_IN_LEDGER']
(2) 본문 + HS-03 둘 다                       -> [막힘]   ['WORD_NOT_IN_LEDGER']
(3) HS-03 만                                 -> [뚫림!!] []
(4) HS-77 로 세탁한 뒤 본문에서 사용            -> [막힘]   ['CLAIM_VALUE_NOT_ANCHORED','STATEMENT_WITHOUT_SOURCE','WORD_NOT_IN_LEDGER']
```

**나쁜 소식이자 좋은 소식이다.** 새는 곳이 `HS-` 문단 한 자리이고, 고치는

## 14. 고치는 법 — 검사원이 보기에

**고칠 곳은 세 군데다. 셋 다 이미 코드 안에 답이 있다.**

1. **`revise()`가 `HS-` 문단을 걷어내고 Harness가 다시 만들게 한다.**
   `_write_draft`가 하는 그대로다. 이러면 `L1`·`M3`과 `K2`의 절반이 함께
   닫힌다. `NEXT.md` 4번이 적은 *"그 자리를 AI가 자유롭게 쓰지 못하게 바꾼다"*
   가 바로 이것이고, 부칙 자리에서 이미 통했다.

2. **`REVISION_DROPPED_RULE`이 번호 대신 글을 보게 한다.** 부칙 문장이 이전
   초안에 있던 그대로 남아 있는지 견주면 된다. 1번을 하면 부칙 문단이 Harness
   소유가 되므로 자연히 해결되지만, **둘 다 하는 편이 안전하다.**

3. **`WRONG` 사실 검사를 `finalize`와 `download_draft`로 옮긴다.**
   `check_revision` 안에만 두면 고치기를 안 하는 사람에게는 없는 것과 같다.

**규칙을 새로 만드는 일은 하나도 없다.** 있는 검사를 **빠진 자리에 걸기만**
하면 된다.

## 16. 검사원이 보는 것

**5일차는 4일차와 다르게 나왔다.**

4일차는 열세 번을 받으며 같은 병이 세 번 되풀이됐다 — 낱말 목록에 경계를
긋고, 거짓말이 그 바깥에 놓였다. 5일차의 뚫린 곳은 **성격이 다르다.**
낱말 목록 문제가 아니라 **"어느 자리를 믿는가"** 문제다. 그리고 그 답은
`_write_draft`에 이미 쓰여 있다. `revise()`가 그 줄을 안 옮겨 왔을 뿐이다.

**시험은 크게 좋아졌다.** 아무것도 안 지키는 시험이 4일차 72개에서 오늘
0개다. `rule_id`를 하나씩 이름 대고 보는 방식이 통했다. 대조군
(`test_아무것도_안_바꾼_수정본은_통과한다`)을 같이 둔 것도 옳다.

**`K4`는 튼튼하다.** 11가지 실패에서 11번 다 이전 초안이 살아남았다. 5일차의
핵심 위험 둘 중 하나 — *"고치다가 멀쩡하던 것까지 잃는다"* — 는 막았다.

**나머지 하나 — *"고치는 과정에서 값이 조용히 사라진다"* — 는 아직 열려 있다.**
부칙이 그렇고(`K2`), "틀렸다"고 한 값이 그렇다(`M4`).

**그리고 새로 생긴 위험이 하나 있다.** 4일차까지 위험은 "없는 것이 들어온다"
였고 5일차 합격선은 "있던 것이 나간다"를 겨눴다. 그런데 실제로 뚫린 `L1`은
**5일차에 다시 열린 4일차 위험**이다. 고치기 기능이 초안 검사에 **뒷문을
냈다.** 새 기능을 붙일 때는 **그 기능이 옛 검사를 어떻게 우회시키는지**를
먼저 봐야 한다.

**넘어가는 조건에 대하여.** `NEXT.md`가 4일차에 정한 규칙(3번)은 *"`F`·`H` 중
하나라도 어겼으면 멈추고 고친다"*였다. 5일차에는 그런 규칙이 아직 없다.
`L1`은 `F1`·`F4`·`H1`·`H2`를 한꺼번에 다시 여는 항목이고, `M3`·`M4`는
**파일이 프로그램 밖으로 나가는 자리**다. 검사원이 보기에 이 넷은 **고치고
다시 받는 쪽**이다. 고칠 곳이 세 군데뿐이고 새 규칙을 만들 필요가 없으므로
오래 걸리지 않는다. 다만 **넘어갈지 말지는 주석님이 정한다.**
