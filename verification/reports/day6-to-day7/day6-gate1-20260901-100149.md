**원본에는 인쇄된 모습이 이렇다.**

문제가 **둘 겹쳐 있다.** NEXT.md는 하나만 적었다.

   `의안` → `번호` → `숫자` 순서를 요구한다. **자릿수를 고쳐도 이 패턴은

`0개 발견`으로 차단된다. 설령 `7285`를 읽어도 `distinct = {7285, 2207285}`가
되어 `자료마다 의안번호가 다릅니다`로 다시 막힌다.

우회할 곳도 없다"고 적었지만, 없앤 것은 *예외*이고 목록 자체의 구멍은 그대로다.
`법률이 되다`·`법이 되다`는 효력 낱말을 하나도 쓰지 않고 효력을 주장한다.

### 5-3. `C3` `다는`/`라는` 오탐 — **살아 있음. 원인을 정확히 짚었다**

`backend/app/gates/draft_gate.py:171` · `1205` · `1239`

```python

...
```

`speaker_here`는 **문단 전체**에서 계산하는데, 그 판정을 **문장마다** 다시 쓴다.
즉 문단 어딘가에 `의원`이 있으면 그 문단의 **모든 문장**이 화자를 가진 것으로
취급된다.

`의원` 유무만 바꿔 격리했다.

```
[인용으로 봄] 의원 있음 + '다는'   '조계원 의원실은(는) 제7조가 바뀌었다는 사실을 알린다.'
                                → rules=[... 'STATEMENT_WITHOUT_SOURCE' ...]
[안 봄]       의원 없음 + '다는'   '제7조가 바뀌었다는 사실을 알린다.'
                                → rules=[...]  (STATEMENT_WITHOUT_SOURCE 없음)
[인용으로 봄] 의원 있음 + '라는'   '조계원 의원실은(는) 원안가결이라는 결과를 알린다.'
                                → rules=['CLAIM_VALUE_NOT_ANCHORED', 'STATEMENT_WITHOUT_SOURCE']
[안 봄]       의원 없음 + '라는'   '원안가결이라는 결과를 알린다.'
                                → rules=['CLAIM_VALUE_NOT_ANCHORED']
[안 봄]       의원 있음 + 어미 없음 '조계원 의원실은(는) 제7조가 바뀐 사실을 알린다.'
[안 봄]       의원 없음 + 어미 없음 '제7조가 바뀐 사실을 알린다.'
```

`원안가결이라는 결과를 알린다`는 **누구의 말도 옮기지 않는다.** `라는`은
관형형 어미다. 그런데 문단에 `의원실`이 있다는 이유만으로 "공식 발언문 없이
사람·기관의 말을 옮겼다"로 막힌다. 지금은 지시문으로 이 어미를 안 쓰게
우회하고 있고, 그래서 초안 문체가 뻣뻣해진다(NEXT.md 2번과 같은 뿌리다).

```python
def _line_of(raw_text: str, quote: str) -> int:
    packed_quote = _packed(quote)
    if not packed_quote:
        return 0
    head = packed_quote[: min(8, len(packed_quote))]     # ← 앞 8글자만 본다
    packed_seen = ""
    for number, line in enumerate(raw_text.splitlines(), start=1):

        if head in packed_seen:

    return 0
```

계약 `verification/day-gate-verifier.md`가 지정한 결정형 검사
`scripts/verify-day1.ps1:423`

```powershell
# .env 를 코드가 읽지 않는지 (예시 파일과 이름 안내는 허용)
$envReaders = $scanFiles | Where-Object { $_.Extension -in @(".py",".ts",".tsx") } |
    Select-String -Pattern "load_dotenv|dotenv" -List
if ($envReaders) { Fail-Check $c7 ... }
else { Add-Evidence $c7 "1일차 코드는 .env를 열지 않음" }
```

라이브러리 이름 `load_dotenv|dotenv`만 찾는다. 그런데 6일차가 넣은 `.env` 읽기는
**직접 만든 함수**다.

- `backend/app/infrastructure/openai_gateway.py:606` `ENV_FILE = SCHEMA_DIR.parent / ".env"`
- `:618` `def load_env_file(...)` → `:633` `target.read_text(encoding="utf-8")`
- `backend/app/main.py:49`가 서버가 뜰 때마다 이것을 부른다

```
$ grep -rn "load_dotenv\|dotenv" backend/app frontend/src
(결과 없음)
```

**그래서 script는 지금도 `1일차 코드는 .env를 열지 않음`이라고 적는다. 거짓이다.**
`.env`를 읽는 것 자체는 6일차의 의도된 설계이므로 문제 삼지 않는다. 문제는
**자동 검사가 그 사실을 못 본 채 통과 증거를 만든다**는 것이다. 증거 문구가
사실과 다르면 다음 관문이 그것을 믿는다.

이 때문에 `scripts/verify-day1.ps1`은 **돌리지 않았다.** 두 가지 이유다.
① 보고서를 `verification/reports/day1-to-day2`에 쓰는데(`:19`) 이번 검토에
허용된 폴더가 아니다. ② 이 script는 **1일차**를 판정하는 것이고 이번 관문은
6일차다. 대신 그 script가 재는 항목(파일 존재, 한 주소 시작·종료, 백엔드
pytest, 화면 test·typecheck·production build, health·SPA smoke, 비밀·CORS 검사)을
**직접 따로 돌려** 4절·9절에 증거로 남겼다.

## 11. 이 보고서의 한계

- 이 검토는 **6일차 관문 1차**다. 계약이 요구하는 재검토는 이 지적들이 처리된
  뒤 **새 문맥에서** 다시 해야 한다.
- 첨부 JSON은 `verification/day-gate-result.schema.json`을 그대로 통과하도록
  썼다. 그런데 그 schema는 `gate_id`를 `"DEMO-DAY1-GATE"` 상수로,
  `check_id`를 `D1G-01~07`로 **1일차에 고정**해 두었다. 6일차 관문을 담을
  칸이 schema에 없다. **`gate_id`의 `DAY1`은 검사 대상이 1일차라는 뜻이 아니다.**
  실제 대상은 `run_id`(`day6-gate1-…`)와 이 문서가 가리킨다.
  참고로 5일차 보고서는 schema를 따르지 않고 `DEMO-DAY5-GATE`를 썼다.
  **schema를 하루별로 확장할지 정하는 것도 남은 일이다.**
- 검사원은 코드를 **한 줄도 고치지 않았다.** 재현 script 3개는 전부
  scratchpad에만 썼고 저장소에 남기지 않았다.
