제목에 `위원회`가 있고 `본회의`가 **함께** 있으면 살아남는다(그래서 §4.1의

### 4.3 왜 차단으로 올리는가

직전 관문이 `B4`를 차단한 근거를 그대로 적용한 것이다.

1. **§3.7 누적 3일차 종료 조건의 뒷절반이 깨진다.** 두 공식 자료가 서로 다른 값을
   적었는데 초안 없이 멈추지 않고 지나간다.
2. **방향이 열리는 쪽이다.** 값 하나가 사라지고 남은 하나가 확정 사실이 되므로,
   결과적으로 시스템이 **말없이 한쪽을 고른 것**과 같다.
   README 656행(자료 간 사실 충돌 자동 선택 금지), 876행(날짜와 요일을 자동으로
   고치지 않는다)을 어긴다.
3. **기록이 없다.** 버린 이유가 어디에도 없어 사람이 되짚을 수 없다.
4. **직전 관문과 같은 종류다.** 직전 `B4`가 `FAIL`이었고, 그 `B4`의 세 갈래
   (`B4-1` 고정 자료 제목 삭제 / `B4-2` 제목의 위원회 / `B4-3` 평문) 중
   **`B4-1`·`B4-3`만 고쳐지고 `B4-2`가 남았다.** 같은 잣대를 써야 한다.
5. **4일차는 초안을 붙이는 날이다.** 지금 상태로 초안을 붙이면 두 공식 자료가 다른
   의결일을 적었는데 시스템이 한쪽을 골라 보도자료 초안에 적는다.

**참작한 사정(결론을 바꾸지 않는다)**: 문제는 개발용 가짜 추출기
`fake_agents.py`에 있고, Gate(`conflict_gate`·`evidence_gate`) 자체는 멀쩡하다.
받은 사실만 놓고 보면 정확히 동작한다. 다만 직전 관문도 같은 파일의 문제로
차단했다.

### 5.1 왜 차단으로 올리지 않는가 — 그리고 어느 쪽이 더 나쁜가

**검사원의 판단: 누락(조용히 사라짐)이 거짓 충돌(사람에게 물어봄)보다 훨씬 나쁘다.
담당자가 고른 방향은 옳다.** 근거는 셋이다.

1. **방향.** 누락은 두 값 중 하나를 시스템이 말없이 버리고 남은 하나를 확정 사실로
   올린다 — 시스템이 사람 대신 고른 것이다. 거짓 충돌은 두 값을 모두 보여 주고
   멈춰서 묻는다. 검사원이 돌린 모든 `N-1` 시나리오에서 `draft_version=0`이었다.
2. **§3.7 종료 조건.** "부족·충돌 자료는 초안 없이 쉬운 질문에서 멈춤"은 거짓 충돌도
   만족한다. 누락은 "정상 자료는 사실과 원문 근거가 연결"과 "충돌 자료는 멈춤"을
   **둘 다** 깬다.
3. **되짚을 수 있는가.** 거짓 충돌은 눈에 보이고 사람이 답할 수 있다.
   누락은 보이지 않아 사람이 알아볼 방법이 없다.

이 판단은 1차 관문이 `N-1`을 미룬 근거("막히는 방향은 닫히는 쪽이며 초안을 지어내지
않는다")와도, 3차 관문이 `B4`를 차단한 근거와도 일치한다. 잣대는 세 번 모두 같다.

### 5.2 다만 `N-1`에는 닫히지 않는 변종이 하나 있다 (`Y-1`)

거짓 충돌이 아니라 **충돌조차 나지 않는** 경우다. 위원회 자료가 본회의 자료에 없는
항목만 가지고 있으면, 비교 상대가 없어 충돌이 나지 않고 **위원회 수치가 본회의 사실로
원장에 들어간다.**

```
Y-1 소관위 평문(재석 24·반대 0만) + 본회의 SR1-S05(재석·반대 줄이 없음)
   state=FAILED BLOCKING=0 draft=0
   본회의 사실: [('vote_present_count','24','SRC-01'),   ← 위원회 값
                ('vote_no_count','0','SRC-01'),          ← 위원회 값
                ('plenary_decided_on','2026. 8. 20','SRC-02'),
                ('vote_yes_count','201','SRC-02')]
Y-3 같은 자료를 COMMITTEE_FINAL_TEXT로 표시하면 -> 위원회 값 제외 (정상)
```

4일차에 초안이 붙으면 **"재석 24명 중 찬성 201명"** 같은 문장이 나올 수 있다.
고정 시험자료 `SR1-S05`가 바로 `재석`·`반대`가 없는 모양이라 남 얘기가 아니다.

**그래도 `B5`와 달리 차단으로 올리지 않는다.** `B5`는 값이 **사라져** 아무 흔적이
없지만, `Y-1`은 값이 **남아 있고** API 응답의 사실마다 `source_name`과 원문 인용이
함께 실린다. 화면에 `재석 24 — 소관위 심사 결과 3행: "재석: 24명"`으로 보이므로
사람이 알아볼 수 있다. 3일차 종료 조건이 요구하는 "사실과 원문 근거가 연결"은
지켜져 있고, 틀린 것은 항목 이름표다. 추출 품질은 README가 6일차로 잡아 둔 몫이다.
**단, `B5`를 고칠 때 반드시 함께 볼 것.**

### 5.3 역할 검사가 겨냥을 잘못했다

`COMMITTEE_ROLES`에는 `COMMITTEE_FINAL_TEXT`(`위원회 최종문`) 하나뿐이다.
그런데 README 1102행의 `SourceRole` 12개에 **`위원회 심사 결과·심사보고서`에 해당하는
역할이 없다.** `위원회 최종문`은 위원회가 정리한 *법안 본문*이지 표결 집계가 아니다.
위원회 표결 수가 적힌 자료를 받은 사용자가 실제로 고를 만한 값은
`의안정보`나 `잘 모르겠음`인데, **그 둘은 보호되지 않는다.**
`N-1d`·`N-1e`가 그래서 뚫린다.

## 10. 차단 문제 (1건)

### `B5` 제목에 위원회 이름만 있으면 본회의 사실이 기록 없이 사라진다

- **어디**: `backend/app/infrastructure/fake_agents.py` — `_is_plenary_scope()`의 제목 분기
  ```python
  heading = _heading_of(text, index)
  if heading and OTHER_BODY_PATTERN.search(heading) and "본회의" not in heading:
      return False
  ```
- **무엇**: 사용자가 확인한 역할(`role=PLENARY_VOTE_RESULT`)보다 **자료 원문의 제목 줄**을
  앞세운다. 역할은 `COMMITTEE_ROLES`에 해당할 때 빼는 데만 쓰고, **넣는 근거로는 쓰지 않는다.**
- **결과**: 제목에 위원회 이름만 있으면 의결일·재석·찬성·반대가 **기록 없이** 사라지고,
  두 자료가 다른 값을 적어도 멈추지 않으며 한쪽이 확정 사실이 된다.
- **README 근거**: §3.7 누적 3일차 종료 조건 / 656행(자료 간 사실 충돌 자동 선택 금지) /
  876행(날짜와 요일을 자동으로 고치지 않는다)
- **재현**: 고정 `SYN-RISK-001/sources/03_plenary_vote.md`와, 제목이
  `# 문화체육관광위원회 소관 의안 처리 결과`이고 본문에
  `- 의결일: 2026. 8. 21.` `- 재석: 204명` `- 찬성: 199명` `- 반대: 4명`이 적힌 자료를
  **둘 다 역할 `본회의 표결 결과`로** 넣는다 → `BLOCKING=0`, `rejected_evidence=[]`.
  제목만 `# 의안 처리 결과`로 바꾸면 `BLOCKING=4`.
- **쓸 수 있는 재료는 이미 있다.** `build_request`가 payload에 `role=PLENARY_VOTE_RESULT`와
  `role_label=본회의 표결 결과`를 넣어 준다. 역할이 본회의 계열이면 제목 표기가
  무엇이든 넣는 쪽이 맞다. 그리고 값을 버릴 때는 `evidence.problems`에 이유를 남겨야
  `D3G-03`의 원칙과 맞는다.
  *(검사원은 코드를 고치지 않았다. 이 문단은 판단이 아니라 관찰이다.)*

### `D2′`가 4일차 초안 Agent에게 위험한가 — 검사원의 판단

**위험하다. `B5`와 함께 4일차 시작 전에 처리해야 한다.**

4일차의 `DraftWritingAgent`는 `FactLedger`를 읽는다. `_keep_with_evidence`가
`UNKNOWN_SOURCE`를 보지 않으므로, **다른 자료의 문구를 근거라고 붙인 입법 사건**이
원장에 그대로 남는다. 검사원이 재현한 것은 `disposition=REJECTED`,
`occurred_on=2099-01-01`짜리 사건이었다. 같은 조건의 **사실**은 버려지는데
입법 사건으로는 살아남는다. 초안 Agent가 그 원장을 읽으면 **부결됐다고, 2099년에
일어났다고 쓸 수 있는 재료**를 손에 쥔다.

다만 `B5`와 달리 `D2′`는 **가짜 추출기가 다섯 목록을 아직 채우지 않아**(모두 빈 배열)
현재 흐름에서 발현하지 않는다. 그래서 이번 차단 사유로 올리지 않고,
`4일차 초안 Agent를 붙이기 전`을 기한으로 못 박아 둔다. 4일차에 다섯 목록을 채우기
시작한다면 그 시점에는 이미 차단 사유다.

## 12. 개발 4일차로 넘어가도 되는가

**넘어가면 안 된다.**

`B5`를 먼저 고치고, 다른 새 문맥에서 다시 검증해 `DEMO-DAY3-GATE=PASS`를 받은 뒤에
4일차를 시작할 것을 권한다. **4일차는 초안을 붙이는 날**이라는 점이 결정적이다.
지금 상태로 초안을 붙이면, 두 공식 자료가 서로 다른 의결일을 적었는데 시스템이
한쪽을 골라 보도자료 초안에 적는 일이 생긴다.

수정할 때 함께 볼 것(검사원은 코드를 고치지 않았다):

1. **`B5`** — 회의 구분을 **자료 생김새보다 사용자가 확인한 역할을 앞세워** 판단한다.
   역할이 본회의 계열(`PLENARY_VOTE_RESULT`·`PLENARY_FINAL_TEXT`·`PLENARY_AGENDA_TEXT`)이면
   제목 표기와 무관하게 넣는 쪽이 맞다. 값을 버릴 때는 `evidence.problems`에 이유를
   남겨 조용히 사라지지 않게 한다.
2. **`N-1′`·`Y-1`·`R1`** — 반대 방향도 같이 본다. 지금은 `COMMITTEE_ROLES`가
   `위원회 최종문` 하나뿐이라, 위원회 표결 수가 든 자료에 사용자가 실제로 고를
   역할이 보호되지 않는다.
3. **`W1′`·`W3`** — 제목에 `위원회`만 든 본회의 자료와 줄 단위 배제를 시험에 넣는다.
   지금은 둘 다 시험이 0건이고, 그래서 `B5`가 100개 시험을 모두 통과했다.
4. **`D2′`** — 다섯 목록에도 사실과 같은 `UNKNOWN_SOURCE`·`AMBIGUOUS` 검사를 적용한다.
   4일차 초안 Agent가 원장을 읽기 전에 막아야 한다.

이 보고서는 위 snapshot 해시(`a6e3c709f7323b67…`)일 때만 유효하다.
제품 코드·설정·시험이 바뀌면 즉시 `STALE`이며 다른 새 문맥에서 다시 검증한다.

## 13. 검사원이 지킨 것

- 제품 소스·시험·Writing Contract·README·schema를 **한 글자도 고치지 않았다.**
  검증 시작 시점과 종료 시점의 통합 해시가 `a6e3c709f7323b67…`로 같다.
  `git status`에 추가된 것은 `verify-day1.ps1`이 만든 1일차 보고서 2개와 이 보고서 2개뿐이다.
- 실패 기준을 낮추거나 시험을 지우지 않았다. 변이 시험은 scratchpad 사본에서만 했고
  매번 원본으로 되돌린 뒤 원본과 `diff` 일치를 확인했다.
- 패키지 설치·lock 파일 변경 0건. (`jsonschema`는 이미 설치돼 있던 것을 썼다.)
- 인터넷·OpenAI API 호출 0회, 비용 0달러. 가짜 `ModelGateway`만 썼다.
- `.env`를 열거나 불러오거나 출력하지 않았다. scratchpad 사본에서 `.env`·`.env.example`을
  즉시 제외했고 사본 트리에 `.env*` 파일이 없음을 확인했다.
- 코드를 고친 뒤 스스로 PASS 처리하지 않았다.
- `git commit` / `git push`를 하지 않았다.
- 기존 보고서를 덮어쓰지 않고 새 run ID로 추가했다.
- 담당자의 설명을 증거로 인정하지 않고, 세 판의 구현을 나란히 놓고 직접 비교했다.
- 검사에 쓴 포트 8765·8799는 검사 종료 시점에 `LISTEN=0`으로 비어 있다.
