### `D3G-04` 충돌·요일 검사 — **FAIL**

**되는 것.** 값을 직접 넣으면 Gate는 옳게 동작한다.

```
FACT_CONFLICT / plenary_decided_on / BLOCKING
  자료마다 값이 다릅니다. 어느 값도 대신 고르지 않았습니다.
  · 2025. 9. 25. — 의안정보 1행: "본회의 심의: 2025. 9. 25."
  · 2025. 9. 26. — 표결 결과 1행: "본회의 심의: 2025. 9. 26."
```

두 값·두 자료명·두 원문이 모두 보이고 어느 쪽도 자동 선택하지 않는다.
수치 충돌(찬성 240인 vs 199인)도 같은 방식으로 잡힌다.

**차단 1 — 요일 검사가 고정 시험자료의 표기를 못 읽는다.**

```python
WEEKDAY_PATTERN = re.compile(r"\(\s*([월화수목금토일])\s*\)")   # conflict_gate.py:24
```

| 표기 | 인식 |
|---|---|
| `(목)` | 인식 |
| `( 목 )` | 인식 |
| `(목요일)` | **못 읽음** |

`test_sets`의 **모든** 요일 표기는 긴 표기다.

```
SYN-RISK-001/sources/03_plenary_vote.md          - 의결일: 2026. 8. 20.(목요일)
SYN-RISK-001/sources/05_independent_vote_notice.md - 의결일: 2026. 8. 20.(목요일)
SYN-RISK-001/mutations/weekday_mismatch.json     "(목요일)" -> "(금요일)"
```

2026-08-20은 실제로 목요일이다. mutation 문장을 그대로 넣어 보면:

```
"- 의결일: 2026. 8. 20.(금요일)"  ->  Issue 0건        <<< 놓침
"- 의결일: 2026. 8. 20.(금)"      ->  DATE_WEEKDAY_MISMATCH 1건
```

날짜 자체는 `_parse_date`가 `2026-08-20`으로 잘 읽는다. 요일 표기만 못 읽는다.
즉 검사는 있지만 **실제 자료 표기에서는 한 번도 발동하지 않는다.**

**차단 2 — 충돌 mutation 3종이 전체 흐름에서 하나도 안 잡힌다.**

| 변형 | 기대(oracle) | 실제 |
|---|---|---|
| `BASELINE` | 초안 후보 생성 가능 | `FAILED/DAY3_SCOPE_LIMIT`, 사실 10건 (3일차 범위상 정상) |
| `DATE_CONFLICT` | `NEEDS_INPUT` + `FACT_CONFLICT/plenary_decided_on` | `FAILED/DAY3_SCOPE_LIMIT`, **차단 Issue 0건** |
| `COUNT_CONFLICT` | `NEEDS_INPUT` + `FACT_CONFLICT/vote_yes_count` | `FAILED/DAY3_SCOPE_LIMIT`, **차단 Issue 0건** |
| `WEEKDAY_MISMATCH` | `NEEDS_INPUT` + `DATE_WEEKDAY_MISMATCH` | `FAILED/DAY3_SCOPE_LIMIT`, **차단 Issue 0건** |

원인은 충돌 Gate가 아니라 그 앞이다. 충돌한 값이 애초에 사실로 뽑히지 않는다.

- 찬성 수를 뽑는 정규식이 `FACT_PATTERNS`에 아예 없다.
- 의결일 정규식은 `본회의[^\n]{0,20}?(\d{4}…)`라서 같은 줄에 “본회의”라는 낱말을 요구한다.
  고정 자료는 `- 의결일: 2026. 8. 20.(목요일)`이라 안 맞는다.

3일차에는 가짜 추출기 말고 다른 경로가 없다. 그러므로 **3일차 종료 조건의
“충돌 자료는 초안 없이 쉬운 질문에서 멈춤”을 프로젝트가 가진 유일한 충돌 자료로
증명할 수 없다.** 손으로 만든 사실로만 증명된다.

**미룬 것 — 거짓 충돌.** `_conflict_key`가 `kind + subject`만 보고 그 값이 *어느 의안·어느
조문*의 값인지는 보지 않는다. 그래서 정상적인 자료가 틀린 질문을 받는다.

| 고정 자료 | 잘못 잡힌 충돌 |
|---|---|

| `ACTUAL-BLOCK-002` | `대안반영폐기` vs `원안가결`을 `plenary_disposition` 충돌로 |

## 6. 개발 4일차로 넘어가도 되는가

**아니다.** `B1`~`B3`을 3일차 범위 안에서 고치고 다시 검증해야 한다.

권하는 순서(구현 담당자 몫이며 검사원은 코드를 고치지 않았다).

1. `B1` 요일 표기를 긴 형태까지 읽게 하고, 시험을 고정 시험자료가 실제로 쓰는 표기로 바꾼다.
2. `B2` 가짜 추출기가 `의결일`·`찬성/반대/기권 수`를 뽑게 해 `SYN-RISK-001`의 세 mutation이
   실제로 `FACT_CONFLICT`·`DATE_WEEKDAY_MISMATCH`로 멈추게 한다.
3. `B3` 세 mutation을 전체 흐름에 넣는 시험을 추가한다.
4. `D2`는 4일차 초안 AI가 원장을 읽기 전에 함께 처리한다.

수정 뒤에는 소스 해시가 달라지므로 이 보고서는 즉시 `STALE`이며, 다른 새 문맥에서
`D3G-01~07`을 다시 돌려야 한다.
