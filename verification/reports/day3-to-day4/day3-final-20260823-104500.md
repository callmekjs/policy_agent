## 1. 한 줄 결론

**`N-1`은 없어졌다. 그러나 그 대가로 진짜 충돌을 놓치게 됐다.**

`N-1`을 고친 방법이 *어느 회의의 값인지*를 **자료 원문의 markdown 제목 줄**로
판단한다. 그래서 제목 줄이 없거나 제목에 `위원회`가 들어가면 본회의 의결일·재석·

## 3. `N-1`은 정말 사라졌는가 — 사라졌다

담당자의 설명을 믿지 않고 검사원이 시나리오를 **직접 구성**해 7종을 돌렸다.
두 자료 모두 정상이고 역할은 각각 `의안정보`·`본회의 표결 결과`로 확인해 두었다.

| # | 시나리오 | BLOCKING | 본회의 사실 |
|---|---|---|---|
| a | 제목 있는 소관위 + 제목 있는 본회의 (직전 검증과 같은 입력) | **0건** | 4건 |
| b | 제목 없는 소관위 + 제목 있는 본회의 | **0건** | 4건 |
| c | 제목 있는 소관위 + `제501회 국회(정기회) 제2차 본회의` 표기 | **0건** | 4건 |
| d | 소관위 자료에만 `본회의 부의 예정`이 적힌 경우 | **0건** | 4건 |

직전 보고서가 4건(`plenary_decided_on`, `vote_present_count`, `vote_yes_count`,
`vote_no_count`)으로 막힌다고 적은 그 입력이 이제 막히지 않는다. 소관위 값은
본회의 사실로 뽑히지 않고, 본회의 값 4건은 그대로 남는다. **`N-1` 해결.**

고정 시험자료 5종에서도 아무것도 나빠지지 않았다. 수정 전후를 직접 비교했다

## 4. 그 대가 — 진짜 충돌을 놓친다 (차단 `B4`)

이번 검증의 핵심이다. 범위를 좁힌 방법이 **자료 원문의 생김새**에 기대고 있다.

```python
def _is_plenary_scope(text: str, index: int) -> bool:
    line = _line_of(text, index)
    heading = _heading_of(text, index)          # `#`로 시작하는 바로 위 제목 줄
    if OTHER_BODY_PATTERN.search(line):
        return False
    if "본회의" in line:
        return True
    return "본회의" in heading and not OTHER_BODY_PATTERN.search(heading)
```

즉 **줄 안에 `본회의`라는 글자가 있거나, 바로 위에 `#`로 시작하는 markdown 제목이
있고 거기에 `본회의`가 있을 때**만 본회의 사실로 쓴다. 사용자가 화면에서 직접
확인한 자료 역할은 보지 않는다. `build_request`가 이미
`role=PLENARY_VOTE_RESULT`, `role_label=본회의 표결 결과`를 payload에 넣어 주는데도
쓰지 않는다.

### `B4-1` 고정 자료에서 제목 줄 **한 줄**만 지우면 세 충돌이 모두 통과한다

`test_sets/SYN-RISK-001/sources/05_independent_vote_notice.md`에서
첫 줄 `# 본회의 표결 집계 통지`만 지웠다. 나머지 내용은 고정 자료 그대로이고,
mutation도 고정 파일 그대로이며, 자료 역할은 `본회의 표결 결과`로 지정했다.
실제 HTTP 경로 결과다.

| 입력 | 차단 | 화면에 남은 의결일 | 화면에 남은 찬성 수 | 버려진 근거 안내 |
|---|---|---|---|---|
| 고정 그대로 `DATE_CONFLICT` (대조군) | **1건** `FACT_CONFLICT` | `2026. 8. 20`, `2026. 8. 21` 둘 다 | `201`, `201` | 없음 |
| 제목 줄만 지운 `DATE_CONFLICT` | **0건** | **`2026. 8. 20` 하나만** | `201` 하나만 | **없음** |
| 제목 줄만 지운 `COUNT_CONFLICT` | **0건** | `2026. 8. 20` 하나만 | **`201` 하나만** (`202`가 사라짐) | **없음** |
| 제목 줄만 지운 `WEEKDAY_MISMATCH` | **0건** | **없음** | 없음 | **없음** |

**두 자료가 서로 다른 날짜를 적었는데 한쪽이 말없이 사라지고, 남은 한쪽이
확정된 사실로 화면에 오른다.** `rejected_evidence`에도 `evidence.problems`에도
아무 기록이 없어 사람이 알 방법이 없다.

README 656행: `자료 간 사실 충돌 | 자동 선택·재작성을 하지 않고 …`
README 876행: `날짜와 요일이 다르면 자동으로 고치지 않는다.`
지금 코드는 두 규칙을 모두 어긴다. 막는 방식이 아니라 **한쪽을 지우는 방식**으로.

### `B4-2` 본회의 자료 제목에 `위원회`가 들어가면 본회의 사실이 전부 사라진다

| 자료 모양 | 본회의 사실 |
|---|---|
| `# 본회의 표결 결과` + 표결 줄 | 4건 |
| `# 문화체육관광위원회 소관 의안 본회의 표결 결과` + 표결 줄 | **0건** |
| `# 본회의 표결 결과` → `## 표결 집계` → 표결 줄 | **0건** |

실제 국회 자료는 소관위원회 이름을 제목에 같이 적는 일이 흔하고,
하위 제목으로 표결 집계를 묶는 것도 흔하다. `_heading_of`는 제목 단계를 구분하지
않고 **가장 가까운 `#` 줄**만 보므로 `## 표결 집계`가 `# 본회의 표결 결과`를 가린다.

### `B4-3` 평문 붙여넣기에서는 **항상** 사라진다 — 이것이 가장 무겁다

README §2.3은 1차 입력을 `웹 입력창에 붙여 넣은 일반 텍스트`와 UTF-8 TXT·Markdown으로
정하고, §2.3은 PDF·DOCX·HWP에 대해 **"문서를 열어 필요한 본문을 복사해 붙여 넣으세요"**
라고 안내한다. 그렇게 복사한 본문에는 markdown `#` 제목이 없다.

```
본회의 표결 결과
대상 의안번호: 2207285
회의명: 제429회 국회(정기회) 제10차
의결일: 2025. 10. 26.(일)
회의결과: 원안가결
재석: 205명
찬성: 201명
반대: 3명
```

| 코드 | 사실 | 본회의 사실 |
|---|---|---|
| 수정 **이전** | 6건 | **4건** — `PLENARY_DECIDED_ON=2025. 10. 26`, `VOTE_PRESENT_COUNT=205`, `VOTE_YES_COUNT=201`, `VOTE_NO_COUNT=3` |
| 수정 **이후** | 2건 | **0건** |

첫 줄에 `본회의 표결 결과`라고 적혀 있어도 소용없다. `#`이 없으면 제목으로 세지
않기 때문이다. 표만 탭으로 복사한 경우도 같다(본회의 사실 0건).
`(일)`로 잘못 적힌 요일도 사실이 없으니 검사되지 않는다.

즉 **지원 프로필 하나(`일부개정법률안 본회의 의결 결과 안내형`)의 핵심 사실인
의결일·표결 수가 기본 입력 방식에서 통째로 빠진다.**

### 왜 차단으로 올리는가

직전 검증은 `N-1`을 "막히는 방향은 **닫히는 쪽**이며 초안을 지어내지 않는다"는
이유로 미뤘다. 같은 기준을 이번에 적용하면 반대 결론이 나온다.

1. **§3.7 누적 3일차 종료 조건의 두 절반이 모두 깨진다.**
   *정상 자료 →* 평문 본회의 표결 기록에서 의결일·표결 수가 사실로 연결되지 않는다.
   *충돌 자료 →* 서로 다른 값을 넣어도 멈추지 않고 지나간다.
2. **방향이 열리는 쪽이다.** 값이 하나 사라지고 남은 하나가 확정 사실이 되므로,
   결과적으로 시스템이 **말없이 한쪽을 고른 것**과 같다. README가 656·688·769·1024행에서
   반복해 금지한 바로 그 동작이다.
3. **기록이 없다.** 버린 이유가 어디에도 남지 않아 사람이 되짚을 수 없다.
   `D3G-03`이 지키는 "버린 것은 이유를 남긴다"는 원칙과도 어긋난다.
4. **직전 관문이 `FAIL`을 준 것과 같은 종류다.** 직전 `B2`는 "고정 자료의 충돌이
   차단되지 않는다"였고 그것으로 `D3G-04`가 `FAIL`이었다. 지금은 그 고정 자료에서
   제목 한 줄만 지우면 같은 일이 벌어진다. 판정 기준을 일관되게 적용해야 한다.
5. **4일차에 초안이 붙으면 바로 사람에게 보인다.** 두 공식 자료가 다른 날짜를
   적었는데 시스템이 한 날짜를 골라 보도자료 초안에 적는다. 이 프로젝트가 막으려던
   바로 그 사고다.

**참작한 사정(그래도 결론을 바꾸지 않는다)**: 문제는 `fake_agents.py`, 즉 개발용
가짜 추출기에 있고 그 파일은 스스로 "좋은 추출이 목적이 아니다"라고 적어 두었다.
Gate(`conflict_gate`·`evidence_gate`) 자체는 멀쩡하며, 받은 사실만 놓고 보면
정확히 동작한다. 다만 직전 관문이 `B2`를 차단으로 판정할 때도 문제는 같은 파일에
있었다. 같은 잣대를 써야 한다.

## 5. 새 시험이 형식적인가 — 아니다. 다만 절반은 시험되지 않았다

`tests/test_fact_extraction.py`의 `test_위원회_표결_수를_본회의_것과_섞지_않는다`가
진짜 잡는지 **scratchpad 사본**에 변이를 넣어 확인했다. 제품 코드는 한 글자도
고치지 않았다.

| 변이 | 죽은 시험 |
|---|---|
| **M1** 필터를 통째로 제거 (수정 이전으로 되돌림) | **새 시험 죽음** |
| **M6** `PLENARY_SCOPED_KINDS`를 빈 집합으로 | **새 시험 죽음** |
| **M3** `_is_plenary_scope`가 항상 `False` (본회의 사실 전부 버림) | 새 시험 + 고정 자료 시험 3개 죽음 |
| **M4** `_heading_of`가 항상 빈 문자열 | 새 시험 + 고정 자료 시험 3개 죽음 |
| **M2** `OTHER_BODY_PATTERN` 검사를 제거 | **죽는 시험 0개** |
| **M5** `OTHER_BODY_PATTERN`을 `소관위`만으로 좁힘 | **죽는 시험 0개** |
