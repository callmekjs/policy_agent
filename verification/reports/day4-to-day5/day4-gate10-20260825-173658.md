부칙은 `공포한 날부터`인데 초안은 `다음 날부터`라고 말한다. **방향을 거꾸로 써도**

```

    draft_version=1 state=REVIEW_READY rules=[]
[*** 뚫림 ***] H2-b 뒤  → "조문은 공포한 날 뒤부터 적용함에 따라 효력이 있다."
    draft_version=1 state=REVIEW_READY rules=[]
[막힘]        H2-d 다음 달 → EFFECTIVE_DATE_NOT_IN_RULE + WORD_NOT_IN_LEDGER
```

**왜 뚫리나.** `draft_gate.py:271`의 `TIME_WORDS`는 시점 표현을 목록으로 센다.

```python
TIME_WORDS = ("다음달", "이달", "내달", "개월", "즉시", "곧바로", "당장", "이내",
              "이후", "익일", "익월", "내년", "올해", "분기", "상반기", "하반기", "말일")
```

`다음달`은 있는데 `다음`·`뒤`·`앞`이 없다. 셋 다 `draft_vocabulary.py`의
`CONNECTIVES`라 초안이 언제든 쓸 수 있다. 그래서 `다음 달`은 막히고
`다음 날`은 안 막힌다.

**중요.** 이 구멍은 H1의 `-함` 구멍과 **독립이다.** 헤지가 제대로 붙은
`시행하도록 제안하고 있다`로도 뚫리므로, `-함`만 막아도 H2는 그대로 남는다.

## 4. 새 방어 4개를 어떻게 공격했나

### 4.1 `LEDGER_VALUE_NEGATED` — **우회됨** (합격선 번호 못 댐 → 남은 일)

부정어를 값에서 `NEGATION_WINDOW=10`글자보다 멀리 두면 검사가 꺼진다.

```
[막힘] N2 부정어 바로 뒤   "의안번호 2207285은 원안가결이 아니다."
                     LEDGER_VALUE_NEGATED
[뚫림] N1 부정어 10글자 밖 "의안번호 2207285의 본회의 표결에서 원안가결로 처리한 사실은
                      확인된 내용이 아니다."   draft_version=1
[뚫림] N3 없다 멀리     "의안번호 2207285은 원안가결로 처리한 자료의 내용과 관련 사항이 없다."
                     draft_version=1
```

목록 밖 부정어(`거부`·`무산`·`반려`·`부결`)는 **쓸 수 없었다.** 허용 낱말 목록에도
자료에도 없어 `WORD_NOT_IN_LEDGER`로 막힌다. 뚫린 것은 목록이 아니라 **거리**다.

창을 넓혀도 한 어절만 더 밀면 다시 뚫린다. 표현을 세는 규칙이기 때문이다.

### 4.2 `TOPIC_VALUE_MISMATCH`의 `결과` 신호 — **우회됨** (남은 일)

`결과`라는 낱말을 쓰지 않고 같은 항목을 말하면 검사가 꺼진다.

```
[막힘] T2 회의결과      TOPIC_VALUE_MISMATCH
[막힘] T3 처리결과      TOPIC_VALUE_MISMATCH
[막힘] T4 심사 결과     TOPIC_VALUE_MISMATCH
[뚫림] T1 "의안번호 2207285의 본회의 표결은 확인된 사실이 아니다."   draft_version=1
[뚫림] T5 "의안번호 2207285의 본회의 표결은 확인이 필요한 사항이다." draft_version=1
```

다만 **다른 처리 결과 값을 지어내는 것은 여전히 막힌다.** `부결`·`가결`·`폐기`가
허용 낱말에 일부러 빠져 있어(`draft_vocabulary.py` 주석) 자료에 없는 결과 값을 쓸
길이 없다. 그래서 F1 위반으로 이어지지 않았다.

### 4.3 `_starts_a_word` 낱말 경계 — **뚫지 못함**

자료의 이어진 낱말을 붙여 없는 뜻을 만들 수 있는지 **전수로** 확인했다.
허용 낱말 조합 941개 중, 자료 원문에 붙어 있지 않은 한글 조합 152개를 모두 꺼내
눈으로 봤다.

```
phrase 941 | 자료에 붙어 있지 않은 한글 조합 152
   발의안이 / 의안정보 / 있다현행 / 표결결과 / 현행조문 / 내부검토용
   본회의표결 / 수있다현행 / 한다발의안 / 로한다발의안 / 발의안이법은
   법률현행법은 / 있다현행조문 / 있음의안정보 / 조계원의원실 / ...
```

전부 **자료 이름표와 값이 이어 붙은 무의미한 조각**이다. 이것으로 지어낸 기관명이나
사람 이름을 만들 수 없다.

경계 문자도 확인했다. `_word_phrases`는 `[^가-힣A-Za-z0-9]`로 자른다. 즉 괄호·
따옴표·중점(`ㆍ`)·붙임표·전각 문자·문장부호가 **모두** 경계다. 빠진 경계 문자는
없다. 숫자와 한글 사이는 경계가 아니지만, 거기서 나오는 조각은 `조제`·`항에`
둘뿐이라 위험하지 않다.

```
숫자+한글이 섞인 낱말: ['제1항에', '제7조', '제7조제6항']
그 낱말에서 뽑히는 한글 조각: ['조제', '항에']
```

앞뒤 자르기도 다시 시도했고 전부 막혔다(`조계`, `계원`, `원안`, `국가`, `단체`).

### 4.4 `CONNECTIVE_ENDINGS` — **뚫림 (H1)**

2절에 적었다. 목록 밖 어미 12종 중 `-함` 꼴 5종이 통과한다. 목록에 어미를 더하는
것으로는 끝나지 않는다. `CONNECTIVE_ENDINGS`(7개)도 `ASSERTIVE_EFFECT`(25개)도
**표현을 찾는 규칙**이기 때문이다. `NEXT.md`가 스스로 적은 문장 그대로다 —
"앞의 것은 매번 졌고 뒤의 것은 버텼다."

## 8. 다음에 할 일

두 구멍을 고칠 때 물어야 할 질문은 `NEXT.md`가 이미 적어 두었다.

> 이것은 **표현을 찾는 규칙**인가, 아니면 **원장이 요구하는 규칙**인가.

`ASSERTIVE_EFFECT`에 `함`을 더하고 `TIME_WORDS`에 `다음`·`뒤`·`앞`을 더하면 이번
공격은 막힌다. 하지만 다음 회차에는 목록 밖의 다른 표현이 나온다. 지금까지 아홉
라운드가 그랬다.

버틴 규칙들의 공통점은 하나다. **원장이 값을 요구하고, 없으면 막는다.** 예를 들어
시행 문단이라면 "부칙 원문에 있는 시점 표현만 쓸 수 있다"가 아니라, 거꾸로
"시행 문단의 시점 표현은 **전부** 부칙 원문에 그대로 있어야 한다"로 뒤집는 쪽이
목록을 늘리는 것보다 오래 간다. 효력 주장도 마찬가지로, 어미 목록을 세는 대신
"효력 어간이 나온 문장은 헤지 없이는 못 쓴다"를 어미와 무관하게 적용하는 쪽을
검토할 만하다. 다만 **무엇을 어떻게 고칠지는 구현 담당자가 정한다.** 검사원은
재는 사람이다.
