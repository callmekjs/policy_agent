## 이번 실행이 새로 찾은 것 3가지

### ① 판번호가 두 개고, 하나는 AI가 정한다

`orchestrator.revise`가 수정을 받아들일 때:

```python
run.draft_history.append(previous)
run.draft = revised                       # 이 안의 version은 AI가 준 값
run.draft_version = previous.version + 1  # 이쪽만 Harness가 센다
```

`DraftCandidate.version`은 AI 응답을 그대로 `model_validate` 한 값이고
(`draft_contracts.py:80`), `_draft_view`가 그것을 `"version"`으로 화면에 보낸다
(`api/runs.py:145`). 화면은 **서로 다를 수 있는 판번호 두 개**를 받는다.

- 가짜 AI: 위·아래 둘 다 `1 → 2`. 안 드러난다
- 진짜 AI(`RUN-66225F9E2B73`): 수정 기록은 `outcome: APPLIED`·`resulting_version: 2`,
  막은 규칙 0건인데 **`draft.version`은 1에 머물렀다**

게다가 `run.draft_version = previous.version + 1`은 **AI가 준 이전 판번호**로 센다.
AI가 계속 `1`을 주면 몇 번을 고쳐도 `draft_version`은 2에서 멈춘다.

값을 지어내지 못하게 막는 것이 이 프로그램의 요지인데, 사람이 보는 판번호가
AI 손에 있다.

### ② 진짜 AI가 빈 상태 코드를 주면 초안이 통째로 막힌다

막은 규칙: `STATUS_CODE_UNKNOWN`

> 문의처의 알 수 없는 상태 코드 ``입니다. 쓸 수 있는 것: `MISSING`,
> `NEEDS_CONFIRMATION`, `NOT_APPLICABLE`, `OK`.

네 값 중 하나여야 하는 자리에 모델이 **빈 문자열**을 넣었다. 4회 중 2회 그랬다.
검사가 막은 것 자체는 옳다 — 문제는 **막을 일이 애초에 안 생기게** 응답 형식이
네 값만 받도록 좁혀져 있지 않다는 것이다.

### ③ `TS-V-02` — 무엇이 빠졌는지 사람이 알 수 없다

README가 요구하는 것:

| 사례 | 뺀 자료 | README가 요구하는 차단 Issue |
|---|---|---|
| A | 본회의 표결 결과 | `REQUIRED_SOURCE_MISSING` + `PLENARY_VOTE_RESULT` |
| B | 최종 의결 내용(발의안) | `REQUIRED_SOURCE_MISSING` + `PLENARY_FINAL_TEXT` |

실제로 나온 것: **A도 B도 똑같이** `REQUIRED_SOURCE_MISSING` + `FINAL_TEXT_DERIVATION_UNSAFE`.
`NEEDS_INPUT`으로 멈추고 초안이 0판인 것은 맞지만, **표결 결과가 없는지 최종문이 없는지를
사람이 구분할 수 없다.** 화면은 둘 다 같은 말을 한다.

그리고 두 사례 모두 **외부 AI를 1회 부른다.** README는 이 자리에 `외부 AI 호출 0회`를
적어 뒀다. 필수 자료가 없는 것은 자료만 보면 아는 일인데, 알아보기 전에 돈이 나간다.
